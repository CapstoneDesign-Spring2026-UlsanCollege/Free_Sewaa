# POLICY — Evidence & Receipts

**Source:** Adapted from the [Capstone team startup documents](https://github.com/CapstoneDesign-Spring2026-UlsanCollege/capstone-team-startup-documents/blob/main/class%20library/POLICY%20-%20Evidence%20%26%20Receipt.md).  
**Team repo:** [Free_Sewaa](https://github.com/CapstoneDesign-Spring2026-UlsanCollege/Free_Sewaa) — post receipts on the **open Weekly Sprint Packet issue** for that week.

---

## Purpose

Capstone Design uses an **evidence-based grading system**. Verifiable **links in GitHub** show who did what. That keeps grading fair and mirrors professional practice.

---

## The core rule

> **If it isn’t linked, it didn’t happen.**

Work must be visible in GitHub (or linked from the Sprint Packet issue).

---

## What receipts are

Receipts are **links** to concrete work. Each student posts them as a **comment** on the **Weekly Sprint Packet** issue. **Minimum per week: 2–3 links.**

---

## Valid receipts

Examples:

- Pull requests  
- Commits (permalink)  
- Issues opened or closed  
- Review comments  
- Documentation updates in the repo  
- CI workflow runs  
- Screenshots of a working feature **with** context and link to the branch/PR when possible  

---

## Example comment

```text
Contribution receipts (Week N)

PR: https://github.com/CapstoneDesign-Spring2026-UlsanCollege/Free_Sewaa/pull/NN
Issue closed: https://github.com/CapstoneDesign-Spring2026-UlsanCollege/Free_Sewaa/issues/NN
Commit: https://github.com/CapstoneDesign-Spring2026-UlsanCollege/Free_Sewaa/commit/HASH
```

---

## What does not count

- Claims without links  
- Only “I helped the team” with no individual trace  
- Work that never appears in the repo or linked artifacts  
- Screenshots with no way to verify source  

---

## Where to post

**Only** as comments on the **Weekly Sprint Packet issue** for that sprint (not random threads), unless the instructor says otherwise.

---

## Why this policy exists

- Fair grading  
- Clear individual contribution  
- Early visibility into blockers  
- Habits that match industry code review and audit trails  

---

## Common mistakes

- Starting code without an Issue or board item  
- Forgetting to link the PR in the receipt  
- Dumping screenshots with no PR/issue reference  
- Doing all work the night before the deadline with no incremental GitHub activity  

**Fix:** touch GitHub **during the week** — issues, small PRs, doc edits with links.

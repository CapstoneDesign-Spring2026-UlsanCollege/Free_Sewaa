# 03 - Design and Planning

This section preserves the project's planning history without presenting every early document as the final implementation. Older proposals and diagrams remain valuable evidence of decisions, changes, and tradeoffs.

| Evidence group | What it contains | How to read it |
|---|---|---|
| [Proposals](./proposals/README.md) | Original problem, users, solution, and proposed stack | Starting intent |
| [User research](./user-research/README.md) | User stories, flows, and domain terms | User needs and acceptance ideas |
| [Wireframes](./wireframes/README.md) | Screen plans and navigation diagrams | Visual and interaction history |
| [Architecture](./architecture/README.md) | API, database, frontend, backend, and UML documents | Historical designs plus current comparison |
| [Risk and scope](./risk-and-scope/README.md) | Risks, bugs, lessons, and scope decisions | Constraints and carryover |
| [Planning documents](./planning-docs/README.md) | Roadmap, board, tasks, agreement, and status records | Project-management evidence |

## Evidence Rules

- Preserve available versions; do not manufacture missing iterations.
- Treat plans as intent until implementation or verification evidence supports them.
- Use [Final Architecture](../04-final-product/ARCHITECTURE_FINAL.md) for the current repository shape.
- Use [Final MVP Scope](../01-project-overview/FINAL_MVP_SCOPE.md) for current feature status.
